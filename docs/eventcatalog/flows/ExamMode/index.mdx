## Overview

Exam mode as it works locally today, started from the page with no CLI step. The hop-by-hop prose is
in `docs/FLOWS.md` section 6.

<NodeGraph />

## Reading the graph

1. **Start.** The server draws tasks by CKA domain weight, saves [exam.json](/docs/containers/ExamFile/0.0.1)
   and replies 202 straight away. The cluster is shared, so at most one task that breaks it for everyone
   (etcd, scheduler, kubelet) is drawn, and it is question 01.
2. **Setup.** One wait, shown as stages: lab, heal, the setups together, then the cluster-wide one.
3. **Clock.** It starts only when every task is ready, so setup time is not exam time and no question is
   locked.
4. **Work.** The user works in the terminal and `ssh`es to each task's node. A server restart keeps the exam.
5. **End.** Every `check.sh` runs at once and each task counts by its weight; 66% passes. Then the cluster
   is tidied for the next exam.

The hosted plan for the same journey is [Quiz Attempt Lifecycle](/docs/flows/QuizAttemptLifecycle/0.0.1).
